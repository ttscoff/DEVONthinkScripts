# Dylan 1.0

**Async Dynamic HTTP Router for Local Services**

Built with Ruby 4.0 + async-http for non-blocking concurrent requests.

---

## Features

✅ **Plugin-based routing** - Simple Ruby classes, no framework overhead
✅ **Non-blocking** - Slow APIs don't freeze other requests (async/fiber-based)
✅ **Ruby 4.0 powered** - Modern syntax with `it` parameter and performance
✅ **Robust error handling** - Circuit breaker, timeouts, safe plugin loading
✅ **Scheduled tasks** - Built-in cron for monitoring, updates, etc.
✅ **YAML redirects** - No-code URL shortcuts via config file
✅ **Management UI** - Debug routes and stats at `/dylan`
✅ **Docker-ready** - Single container deployment on Synology/Mac/Linux

---

## Performance

- **5,500+ requests/second** (Mac mini M4)
- **2,500+ requests/second** (Synology DS224+)
- **Per-plugin timeouts** (default 500ms, customizable)
- **Circuit breaker** (auto-disable failing plugins after 5 errors)

---

## Use Cases

- **URL shortcuts**: `/g/ruby` → Google search, `/gh/user/repo` → GitHub
- **Deep links**: DEVONthink searches, Apple Notes lookups via Shortcuts
- **API proxies**: Weather data, monitoring dashboards, webhooks
- **Network tools**: Synology CheckIP emulation, device monitoring

## Quick Start

### Prerequisites

- **Synology NAS**: Docker + Portainer installed
- **Mac/Linux**: Docker or OrbStack

### 1. Get Dylan

```bash
# On Synology
cd /volume1/docker
git clone <repo> dylan

# On Mac
cd ~/docker
git clone <repo> dylan
```

### 2. Configure Your Setup

**Edit `config/redirects.yaml`** for simple URL shortcuts:

```yaml
redirects:
  - pattern: '^/g/(.+)$'
    target: 'https://google.com/search?q=${1}'
    description: 'Google search'
```

**Edit `config/crontab`** for scheduled tasks (optional):

```bash
# Run monitor every 5 minutes
*/5 * * * * /app/scripts/monitor.sh > /proc/1/fd/1 2>&1
```

### 3. Deploy

**Synology (Portainer):**
1. Import `docker-compose.yml` as new stack
2. Adjust IP address in network config (see [DEPLOYMENT.md](DEPLOYMENT.md))
3. Deploy

**Mac (OrbStack/Docker):**
```bash
docker-compose -f docker-compose.mac.yml up -d
```

### 4. Access

- **Main server**: `http://your-ip/`
- **Management UI**: `http://your-ip/dylan`
- **Routes list**: `http://your-ip/dylan/routes`
- **Stats**: `http://your-ip/dylan/stats`

## Creating Your First Plugin

```ruby
# plugins/70-wikipedia.rb
class WikipediaPlugin < Dylan::Plugin
  pattern(%r{^/w/(.+)$})

  def call(host, path, request)
    query = path.match(%r{^/w/(.+)$})[1]
    Dylan::Response.redirect("https://en.wikipedia.org/wiki/#{query}")
  end
end
```

**With custom timeout:**
```ruby
class SlowAPIPlugin < Dylan::Plugin
  pattern(%r{^/api/slow})
  timeout(3.0)  # 3 seconds for external API calls

  def call(host, path, request)
    # External API call here
  end
end
```

**Test it:**
```bash
curl -I http://your-server/w/Ruby_programming
# → 302 redirect to Wikipedia
```

**Reload plugins:**
```bash
docker restart dylan
```

```ruby
Dylan::Response.html("<h1>Hello</h1>")

# JSON
Dylan::Response.json({ status: "ok", data: [1,2,3] })

Dylan::Response.text("Hello World")

# Custom response
Dylan::Response.custom(
  status: 418,
  headers: { 'x-teapot' => 'true' },
  body: "I'm a teapot"
)

# 404
Dylan::Response.not_found
Dylan::Response.error(500, "Internal error")
```

## Robustness Features

### 1. **Per-Plugin Timeouts**
```ruby
class MyPlugin < Dylan::Plugin
  timeout(2.0)  # Override default 500ms timeout
end
```

### 2. **Circuit Breaker**
Automatically disables plugins that error 5+ times:
```
❌ ERROR in BadPlugin: timeout exceeded (path: /api)
   Error count: 1/5
...
🚨 CIRCUIT BREAKER: BadPlugin disabled after 5 errors
```

### 3. **Safe Plugin Loading**
Syntax errors in plugins won't crash the server:
```
🚫 FAILED to load 99-broken.rb: syntax error
   Location: /app/plugins/99-broken.rb:15
✅ Loading: 60-weather-demo.rb
```

### 4. **Error Recovery**
Individual plugin errors don't stop request processing - router tries next plugin.

---

## Routing Rules

1. **Load order**: Alphabetical by filename (`00-*.rb` before `50-*.rb`)
2. **First match wins**: First plugin matching the pattern handles the request
3. **Return stops routing**: Once a plugin returns a response, routing stops
4. **No priorities**: Simple, predictable order based on filenames

## Why Async?

**Problem without async:**
```
Browser 1: /weather/Berlin (2s) → Server busy
Browser 2: /g/ruby             → Waits 2s for weather!
Browser 3: /monitor            → Waits 4s total!
```

**With async (Dylan 1.0):**
```
Browser 1: /weather/Berlin (2s) → Fiber 1 working
Browser 2: /g/ruby              → Fiber 2 responds instantly! (10ms)
Browser 3: /monitor             → Fiber 3 responds instantly! (10ms)
```

## Ruby 4.0 Features

Dylan leverages modern Ruby 4.0 syntax:

```ruby
# Core uses 'it' parameter for cleaner code
plugin_files.each { puts "Loading: #{File.basename(it)}"; require it }

# Plugins stay explicit for readability
@plugins.each do |plugin|
  plugin.call(host, path, request)
end
```

### Experimental Features (Optional)

Enable cutting-edge Ruby 4.0 features in `config/runtime.yaml`:

**Ruby::Box** - Plugin Sandboxing:
```yaml
ruby_box:
  enabled: true  # Isolates each plugin in separate execution context
```

**ZJIT** - Zero-overhead JIT Compiler:
```yaml
zjit:
  enabled: true  # Faster than YJIT for long-running processes
```

Then start Dylan with:
```bash
# For ZJIT
RUBY_ZJIT=1 ruby server.rb
# Or: ruby --zjit server.rb
```

**Note**: These features are experimental and may not be stable. Use at your own risk.
